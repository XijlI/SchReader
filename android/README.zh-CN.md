# SchReader 手机版（安卓 App）

把同一套「论文网页 → Nature 式阅读版式」搬到手机上。手机浏览器装不了 Chrome 扩展，
所以这里是一个原生安卓 App：内置 WebView 当浏览器用，右下角一个悬浮按钮，点了就用
**同一套解析器 + 同一个阅读页**（`extension/` 里的代码）重排当前论文。

```
打开 App
 └─ 直接是「我的文库」，底部三个标签：文库 · 搜索 · 设置
     ├─ 文库   收藏的论文、标签、备注、导入导出、阅读历史（和浏览器扩展是同一个页面）
     ├─ 搜索   Google Scholar + 默认的 Nature / Science / Cell，「+ Site」可以自己加期刊官网
     │        搜索框里的词交给 Scholar；直接输网址也能打开
     └─ 设置   主题、阅读字体与字号、阅读历史开关、版本号
     └─ 点某个站点或文库条目 → 浏览器视图
          ├─ 顶栏地址栏：输入网址或搜索词（没有点的词就当 Scholar 搜索）
          ├─ 学校/机构登录照常走网页流程，登录状态留着（cookie 常驻）
          └─ 点进论文页 → 右下角悬浮按钮「N 阅读版式」
               └─ 解析 → App 内置阅读页（17 套主题 / 划词高亮 / 灯箱 / 三标签侧栏）
                   └─ 顶栏「原文 ↗」→ 回到出版社原页
往下滑时底部标签栏自动收起，往上滑立刻回来；返回键：设置/搜索 → 文库，文库 → 你刚才读的那篇，再按退出。
```

## 安装

最省事：[Releases 页面](https://github.com/303035/SchReader/releases/latest) 下载
`schreader-android-vX.Y.Z.apk`，直接从下面第 1 步开始 —— 它用发布密钥签名，能覆盖安装旧版本。
在电脑上下载 APK 再传到手机，或者直接用手机打开 releases 页面下载。

第一个发布版 APK（v0.1.0）要先卸载旧的调试版 —— 那个用的是本机调试密钥，签名对不上。

自己构建的话，APK 在 `android/app/build/outputs/apk/debug/app-debug.apk`。

1. 把 APK 传到手机（`adb push ... /sdcard/Download/`，或直接拷文件）
2. 文件管理 → 下载 → 点 APK 安装（允许「未知来源」）
3. 若用 adb 直接装，魅族需要先打开 **设置 → 系统 → 开发者选项 → USB 安装**，
   否则报 `INSTALL_FAILED_USER_RESTRICTED`。打开后：
   ```
   adb install -r -g app-debug.apk
   ```

## 用法

| 操作 | 效果 |
|---|---|
| ‹ / › | 后退 / 前进（没有可去的历史时对应箭头变暗） |
| 地址栏输入 | 网址直接打开；没有点的词当 Scholar 搜索；**点一下自动全选整条网址**（打一个字就替换掉） |
| ⟳ | 重新加载 |
| **长按 ⟳** | 在「手机版 / 桌面版」之间切换（箭头变金色 = 现在是桌面版） |
| **地址栏右侧 100%** | 网页缩放：点开 `− 100% + 重置`，档位 75/85/100/115/130/150/175/200%；非 100% 时数字变金色，选择会被记住（只作用于出版社页面；阅读页用顶栏 `Aa` 调字号） |
| ☆ | 收藏当前页（只存网址 + 标题，不存正文） |
| 底部标签栏 | 文库 / 搜索 / 设置 —— 阅读时自动收起，往上滑一下回来；有网页时点"搜索"先回到那个网页，再点一次才回搜索主页 |
| 右上角数字 | 当前标签页数量 —— 点开标签列表（切换 / 关闭 / `+ New`），最多 8 个，重开 App 自动恢复；阅读页里用工具栏的 `❐` 打开同一份列表 |
| 回到原处 | 从阅读页去文库或切到别的标签，回来还是阅读页那一屏（不是网页原文） |
| 25%…200% | 页面缩放；点开后的 `−` `+` 小面板就在这个按钮正下方 |
| 悬浮按钮「N 阅读版式」 | 解析当前页并打开阅读页 |
| 返回键 | 阅读页 → 原文页 → 上一页 → 刚才的文库 → 退出 |
| 分享链接到本 App | 微信/mail 里分享文本，会自动取出其中的网址打开 |

### 关于「这个站点把 App 内置浏览器拦了」
部分出版商的自动化访问防护会拦内置浏览器（Elsevier/ScienceDirect 的
`There was a problem providing the content` + `CPE00001`）。实测结论：

- 同一台手机、同一个 IP，**Chrome 能开**，说明不是网络问题；
- 桌面 UA 反而更容易被拦 —— 因为 UA 说 Windows、客户端提示（Sec-CH-UA）还说
  Android，指纹自相矛盾；
- 真正的原因是 WebView 默认 UA 会暴露完整机型和系统 build（`MEIZU 20 Build/TKQ1…`）。
  App 现在改用**真实 Chrome 的精简 UA**（`Android 10; K` + `Chrome/<主版本>.0.0.0`），
  ScienceDirect 正文页已实测能进、能重排。

如果还有站点拦，App 会明确提示「被内置浏览器拦了」而不会假装解析失败；这种站点用
Chrome 打开即可（代价是没有阅读版式）。

### 手机版页面解析不出来怎么办
有些出版商的手机版网页结构跟桌面版不同（PLOS 手机版甚至把全文藏在折叠面板里）。
点「阅读版式」后如果正文太少，App 会**自动换桌面版 UA 重新加载并再解析一次**。
还不行就长按 ⟳ 手动切桌面版（手机上桌面版排版会很挤，需要双指缩放，只当兜底）。

## 重新构建

```bash
cd android
./build.cmd          # 或者 Windows 下双击 build.cmd
```

`build.cmd` 会先跑 `tools/mirror.py`：把 `../extension/reader.html/css/js`、
`fonts/` 和 7 个解析器文件**镜像**进 App 的 assets（这些副本不进 git），
再 `gradlew.bat assembleDebug`。

**只有一份源码**：改 `extension/` 里的阅读页或解析器，重新 build 就同时更新
Chrome 扩展和手机 App，不会出现两份代码漂移。

依赖：JDK 21 + Android SDK 36（`android/local.properties` 里的 `sdk.dir`）。

## 已知限制（不粉饰）

- **正文在独立 iframe 里的站点抓不到**：WebView 的 `evaluateJavascript` 只作用于主框架，
  扩展里的 `all_frames` 那套在 App 里没有对应能力。阅读页会提示「正文太少」。
- **PDF 页面**不能重排，只能用系统 PDF 阅读器打开。
- 手机版页面结构差异较大的站点可能要多补几轮适配器（桌面版已实测通过的：
  Nature / PLOS / PNAS / Wiley / ScienceDirect / Cell / Frontiers）。
- 划词高亮在手机上需要长按选词，测试得比桌面少。
- 图片缩略图用的是出版商给的 `size=medium`，灯箱里"100%"就是中等图；
  要看原图点灯箱右下「Open image ↗」。
