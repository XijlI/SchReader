## 0.4.1 修复

### 从「我的文库」打开的论文终于是完整的

出版社页面说「加载完」的时候，正文往往还没到：先到的是带 citation 元信息的骨架和头一两段，
剩下的正文由页面自己的脚本随后塞进去。以前从文库点「打开」就在那一刻转换，阅读视图拿到的是一份
看着完整、其实缺章节也缺参考文献的模型——而且阅读视图会接管并替换掉那个标签页，没有第二次机会。

- 现在从文库打开会先等页面 `load` 完成，再等正文文字不再增长；如果提取过程中正文还在长，会重新读一遍。
- 用一个「load 之后 3 秒才补齐正文」的页面实测：修之前 2 节 / 0 条参考文献，修之后 8 节 / 12 条
  （22 段）。
- 代价：出版商的页面会多停留约 2.5–3.5 秒才切到阅读视图。
- 自己点胶囊不受影响，仍然立刻转换——你是页面加载好了才点的。

### nature.com 正式支持

- `nature.com` 一直在一份内部的「这个站点本来就像我们」跳过名单里，而这份名单**排在允许站点名单之前**
  判断。所以在设置里添加它完全没有效果：权限给了、内容脚本也注册了，胶囊就是不出现。
- 现在它是内置出版社（名单共 49 个域名），跳过名单里也删掉了；而且**你自己添加的域名优先于跳过名单**，
  以后不会再有第二个站点踩这个坑。
- 线上 nature.com 论文页实测：65 节 / 110 段 / 5 图 / 87 条参考文献。
- 以前手动加过、现在变成内置站点的域名，不再出现在设置面板的「额外站点」里（它本来也没法撤销
  manifest 里的权限）。

### 内部改动

- `manifest.json` 由 `extension/src/whitelist.js` 重新生成（`python3 .github/scripts/sync_whitelist.py`），
  CI 会继续校验两者一致。
- README / README.zh-CN 的「已实测出版社」表加上了 Nature（现在 7 家），删掉了「nature.com 故意不在
  名单里」那句；`docs/INSTALL*.md` 和 `docs/PLAN.md` 同步更正。
