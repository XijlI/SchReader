SchReader turns any publisher's article page into a clean, Nature-like reading layout — one text
column with a fixed **Sections / Figures / References** rail — as a Chrome (MV3) extension and as an
Android app. Both hosts share one extractor, one reader page and one library store.

## Downloads

| File | What it is |
|---|---|

## What is new in 0.4.1

### A paper opened from My library is complete

Publisher pages report themselves "ready" long before the article is: the shell arrives with the
citation metadata and a couple of paragraphs, and the rest of the body is mounted by the page's own
scripts afterwards. **Open** in the library converted at that first moment, so the reading view could
show a plausible but half-built paper — sections missing, no reference list — and it then replaces the
tab, so there was no second chance to read the page again.

- Opening from the library now waits for the page's `load` event, then for the body text to stop
  growing, and re-reads the page if it keeps growing while it extracts.
- Measured on a page that appends its body three seconds after load: 2 sections / 0 references before,
  8 sections / 12 references (22 paragraphs) after.
- Cost: the publisher page stays on screen for about 2.5–3.5 seconds before the reading view opens.
- Clicking the pill yourself is unchanged — it converts immediately, because you clicked after the
  page was ready.

### nature.com is a supported publisher

- `nature.com` sat in an internal "this site already looks like our layout" skip list that was
  checked *before* the allowed-sites list. Adding it in Settings therefore did nothing: Chrome granted
  the permission, the content script was registered, and the pill never appeared.
- It is a built-in publisher now (49 domains on the list), the skip list no longer mentions it, and a
  domain you add yourself now wins over that skip list — so the same confusion cannot hit another
  host.
- A live nature.com article converts to 65 sections / 110 paragraphs / 5 figures / 87 references.
- An older custom entry for a domain that has since become built in is no longer listed as an extra
  site in Settings (its Remove button could not revoke a manifest permission anyway).

### Under the hood

- `manifest.json` regenerated from `extension/src/whitelist.js` with
  `python3 .github/scripts/sync_whitelist.py`; CI checks that the two still agree.
- README and README.zh-CN: Nature added to the verified-publishers table (seven now) and the
  "nature.com is deliberately not on the list" line removed; `docs/INSTALL*.md` and `docs/PLAN.md`
  corrected to match.
