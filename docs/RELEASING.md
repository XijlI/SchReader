# Releasing

Every release publishes three files on GitHub:

| File | Built from |
|---|---|
| `schreader-android-v<version>.apk` | `android/` + `extension/` (mirrored in by `android/tools/mirror.py`) |
| `schreader-chrome-v<version>.zip` | `extension/` |
| `SHA256SUMS.txt` | checksums of the two files above |

The workflow lives in [`.github/workflows/release.yml`](../.github/workflows/release.yml).
It needs **no** local machine: GitHub builds, signs and publishes.

## Cut a release

**Option A — push a tag** (normal path):

```bash
git tag v0.2.0
git push origin v0.2.0
```

**Option B — manual run**, when you don't want to touch git:
GitHub → **Actions** → **Release** → **Run workflow** → type `0.2.0` → **Run**.
The workflow creates and pushes `v0.2.0` for you if that tag doesn't exist yet.

Re-running a version that is already released simply rebuilds and overwrites that
release's assets — handy when a build was broken.

### Before you tag

The release refuses to build when `manifest.json`'s site list has drifted from the canonical list
in `extension/src/whitelist.js`:

```bash
python3 .github/scripts/sync_whitelist.py          # rewrite the manifest from the JS list
python3 .github/scripts/sync_whitelist.py --check  # what the workflow runs
```

### Version numbers

`vMAJOR.MINOR.PATCH`, all parts 0–99. The tag drives everything, no file edits:

- `versionName` in the APK = `MAJOR.MINOR.PATCH`
- `versionCode` (what Android uses to decide "this is newer") = `MAJOR*10000 + MINOR*100 + PATCH`,
  so `v0.2.1` → `201`. `v0.2` is accepted and normalised to `0.2.0`.
- `version` in `extension/manifest.json` is stamped at build time and **not** committed,
  so the repo's checked-in version never goes stale.

Android only installs an update when `versionCode` grows. Never reuse a version.

## One-time setup: the signing key

Android refuses to install an APK whose signing key differs from the installed one, so
releases must always be signed with the *same* keystore. That keystore lives **outside**
this repo, in `<backup-dir>/schreader-release.jks`, and GitHub gets it as repository secrets.

The current key is:

```
CN=SchReader, OU=Personal, O=SchReader, C=CN
SHA-256 32:78:B1:ED:34:01:18:14:62:38:2C:16:9C:72:3C:A1:39:3C:69:EB:53:6D:06:5B:91:CC:22:9C:3D:32:BB:CA
```

It was rotated once, before the first public release: v0.1.0 is the first build signed with this
key, so no installed copy is stranded.

Add these four at **Settings → Secrets and variables → Actions → New repository secret**:

| Secret name | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | contents of `schreader-release.jks.b64` (one long line) |
| `ANDROID_KEYSTORE_PASSWORD` | the store/key password |
| `ANDROID_KEY_ALIAS` | `schreader` |
| `ANDROID_KEY_PASSWORD` | same as the store password |

All four values are written in `<backup-dir>\SECRETS.txt`.

> **Back up that folder.** Lose the keystore and you can never publish an update to
> people who installed an earlier APK — they would have to uninstall first. Keep a copy
> on a USB stick or in a password manager.

If the secrets are missing, the build still succeeds but warns `::warning::` and signs
with a throwaway CI debug key; that APK will not install over an older release.

## Release notes

Generated by [`.github/scripts/release_notes.py`](../.github/scripts/release_notes.py):
English body first, then a collapsible 中文说明 at the end. The changelog is grouped
from conventional-commit subjects (`feat:`, `fix:`, …) since the previous `v*` tag.

To write them by hand instead, add a file before tagging:

```
docs/release-notes/v0.2.0.md         # replaces the English body
docs/release-notes/v0.2.0.zh-CN.md   # replaces the 中文 section
```

## Reproduce a release locally

Same steps as CI, on this machine:

```bash
cd android
export NV_KEYSTORE_FILE='<backup-dir>/schreader-release.jks'
export NV_KEYSTORE_PASSWORD="$(cat <backup-dir>/.storepass)"
export NV_KEY_ALIAS=schreader
export NV_KEY_PASSWORD="$NV_KEYSTORE_PASSWORD"
python3 tools/mirror.py
sh gradlew assembleRelease -PappVersionName=0.2.0 -PappVersionCode=200
```

Output: `android/app/build/outputs/apk/release/app-release.apk`.
Without the `NV_*` variables (i.e. a plain `build.cmd` / `assembleDebug` day) nothing
changes — release builds just fall back to the debug key.

If you prefer a properties file over env vars, create `android/keystore.properties`
(gitignored):

```properties
storeFile=<backup-dir>/schreader-release.jks
storePassword=...
keyAlias=schreader
keyPassword=...
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` on the phone | The new APK is signed with a different key than the installed one. Check the four secrets; if they were never set, uninstall once. The debug APKs built before v0.1.0 use the local debug key, so the **first** release-signed APK needs one uninstall (bookmarks in the app's data are lost with it). |
| Workflow fails at "Set up the Android SDK" | `platforms;android-36` / `build-tools;36.0.0` list in the workflow no longer exists upstream — update the `packages:` line. |
| `Permission denied` on `./gradlew` | The wrapper lost its exec bit in the repo; the workflow runs `chmod +x gradlew` first, do the same locally or call `sh gradlew`. |
| Release body shows "_No commit messages…_" | The previous tag was too far back or history was fetched shallow (`fetch-depth: 0` is required). |
| Extension zip won't load | Chrome needs the **unzipped folder that directly contains `manifest.json`**, not the zip and not its parent. |
